# Diffractor 1.27.1

Baseline: 1.27.0, released 2026-08-07 as build `1.27.0.1269`.

This document lists what 1.27.1 changed. GitHub issues are authoritative for issue state and discussion; the linked documents own the durable behaviour. Work deferred past this release, issues awaiting reporter confirmation, and validation still to run are recorded in [post-release context](v-next.md).

1.27.1 is a maintenance release. It adds no features. It reduces how much memory the program uses while browsing and viewing, makes it faster to draw, and closes a set of defects found by a pre-release review of the code — several of which could lose data or leave the program stuck, but none of which a normal session would have shown.

## Overview

- **Uses much less memory, and stays that way.** Images are no longer decoded ahead of the one you are looking at, thumbnails held in memory are bounded, and images kept from earlier are dropped when they are cheap to rebuild and kept when they are not. Nothing you can see changes; the program simply stops growing while you browse.
- **Browsing is smoother.** Text in the item grid is laid out once and reused instead of being re-shaped on every frame, and reducing an image to thumbnail size no longer takes a slow path through the video scaler. Measured on a 1579-item folder, drawing the grid costs less than half what it did.
- **Your ratings and keywords cannot be lost to a locked sidecar.** Rating or tagging a RAW file whose `.xmp` sidecar was momentarily unreadable — held open by Lightroom, Bridge, a backup tool or a virus scanner — used to replace it with a sidecar containing only the change, and report success. It now refuses the write and tells you why.
- **Duplicate detection stops fading out.** Scrolling a video into view cleared the checksum Diffractor had recorded for it, so copies quietly stopped being reported until the next restart.
- **Video plays in software rendering.** With hardware acceleration off — by choice, with `-no-gpu`, or after a graphics driver failure — video played with sound and a moving scrubber over a picture that never updated.
- **Opening several photos at once no longer resets your layout.** Selecting a few files in Explorer and pressing Enter starts one Diffractor per file. The crash-recovery backstop counted those as repeated failed launches and reverted the sidebar, fonts, panel sizes and hardware acceleration to defaults.
- **Diffractor starts on a display that exists.** A window last used on a second monitor now comes back onto an attached one instead of opening off-screen after you undock.
- **Uninstalling keeps your data.** The uninstaller removed the whole program folder, which is also where the index, settings, map cache and any dictionary you downloaded live, and it removed the settings key with them. It now removes the program, the files it installed and its own logs, and leaves the rest alone.
- **A finished task tells you the truth about which file it was.** Sorting the reviewed list before pressing Run made Convert, Edit metadata and Adjust date report each row's success or failure against a different file. Rename and Tags showed their progress stuck at the first of however many items, with the wrong row highlighted for the whole run.
- **An edit that was not written is no longer reported as saved.** A crop, rotation or format change whose source could not be read reported success having written nothing.
- **Editing metadata in bulk shows up immediately.** Tools ▸ Edit metadata and Adjust date wrote the files but never told the index, so tiles, properties and search kept showing the old values until something else happened to re-read the folder.
- **Convert will not overwrite a file you never saw.** A file that appeared in the destination folder between the review and the run was silently replaced.
- **Added words are remembered on a Store install.** Add to dictionary, and every dictionary download, silently failed there because the program wrote to its own read-only install folder.
- **32-bit builds no longer crash in video decoding.** A stack alignment defect in the vendored FFmpeg assembly.

## Changes

### Memory and drawing

Owned by [file I/O](file-io.md#47-lifetime) and [implementation](implementation.md#thumbnail-pipeline).

- No image is read ahead. Prefetch decoded the previous and next image at a fixed 2560x2560 regardless of window size, so in a 1000-pixel window the two images not being looked at cost more than ten times the one that was. Every image now loads on demand at display size. Thumbnail surfaces for the neighbours are still staged, because they are what the media view shows while the full image arrives.
- Retention of recently displayed images is by *form*, not recency: an image that exists as encoded bytes (JPEG, PNG, WebP, a RAW preview) is cheap to rebuild at display size and is dropped, while one that exists only as a decoded surface (PSD, HEIF, JXL, TIFF, GIF, BMP, a developed RAW) is kept. The byte budget now counts everything retained, rather than one of the five buffers.
- Encoded thumbnails in a result set are bounded to 32 MiB, ranked by distance from the viewport rather than by age, so scrolling back does not return to the database.
- The item grid caches its DirectWrite text layouts instead of re-shaping every string on every frame.
- Reducing a packed 32-bit image is done by an area-average scaler with AVX2 and SSE2 paths rather than through libswscale, which has no RGB-to-RGB scaler and converted to planar YUV and back.
- The thumbnail store is WebP rather than a per-site choice of format, so a cloud thumbnail can no longer be stored as a 110 KB PNG where 19 KB would do.
- Worker threads: four index passes now share one thread, the debounce that used to occupy a worker moved into the queue, and the last periodic wake-ups are gone. Database writes are published in groups rather than one transaction per file.

### Correctness and crash hardening

- A window that has no window: `view_host::frame()` and every `ui::frame_host` accessor answer a null object rather than null, and the scattered guards were removed rather than added to. This closes the class the 1.27.0 startup crash belonged to; see [post-release context](v-next.md#23-absent-windows-and-why-the-guards-were-removed-rather-than-added-to).
- A safe start reverts presentation and turns hardware acceleration off after two launches that never reached the user. Only the launch holding the startup scope counts an attempt, and any launch that reaches the user clears the count.
- A crash report is written and uploaded once, with the log flushed first, and a repeating crash no longer leaves a dump behind on every launch.
- The spelling dictionary reads from the install folder or the per-user folder, preferring the per-user copy, and always writes to `%LOCALAPPDATA%\Diffractor\dictionaries`.
- A metadata sidecar that exists but cannot be read is refused, not rebuilt from the edit alone. The refusal fails that one file; the rest of a batch still runs.
- A checksum is cleared when the file's bytes are seen to change, rather than by any scan that did not happen to read the whole file.
- The write claim that keeps background reads off a file being written is released even when the write throws, instead of parking those items for the rest of the session.
- Every worker is started through the shutdown-latched path, so a close during startup cannot leave threads running past teardown.
- The selector strip records a failed thumbnail decode instead of asking for it again on the next frame.
- Convert re-checks each destination immediately before writing it.
- Batch metadata and date edits report the folders they wrote to, so the index re-reads them.
- A finished run is read against the file each row was built from rather than the row's position, so sorting the reviewed list by a column header before pressing Run no longer reports one file's outcome against another.
- Rename and Tags advance their progress through every item instead of stopping at the first and leaving the second row highlighted for the rest of the run. The row being worked on is now followed by identity, so it stays correct if the list is reordered underneath it.
- The row being worked on is kept where it can actually be seen. It was scrolled to the very edge of the list, which is where the column headers and the status band are drawn over it, so the highlight spent long runs hidden under one or the other. It now stops clear of both with a line of text to spare.
- Tags refuses to run over its own results, as the other tasks already did, and says that an edit is needed rather than only dimming the button. Editing the tags, choosing a suggested word or changing the selection puts the view back into review.
- Neither Tags nor Rename re-plans while its own run is in flight.
- An image that cannot be encoded no longer leaves the shared JPEG encoder unusable, which used to stop thumbnails and Convert from producing anything for the rest of the session.
- A staged write that runs out of disk part way no longer leaves a truncated `diffractor_` file beside the original for the browser to show as a broken image, and a sidecar write that fails no longer strands its staged copy.
- A crop, rotation or format change whose source cannot be read is refused and says so, instead of reporting success having written nothing - or, for a format change, copying the original bytes under the new extension.
- The panel describing a multiple selection or a comparison sits in the middle of the preview pane, as a single item's does. Show verbose metadata held it against the top of the pane, even though those selections have no metadata blocks for the setting to reveal.
- The uninstaller keeps the settings key as well as the data folder.

### Tests

Owned by [testing](testing.md).

The suite was reorganised into thirteen subject files, `test_regressions.cpp` was removed in favour of putting each regression test with the behaviour it covers, and the runner now fails on a duplicate test name, a filter that matched nothing, and a test that asserted nothing. Four rules were extracted so they could be tested at all: playback resume, slideshow advance, the address-box editing session, and the keyboard accelerator table.

## Verification

- `.\dd.ps1 test`: 747 x64 Debug / 753 x64 Release, 0 failures; 13 catalogs, 1187 source strings, 0 structural problems. The six-test difference between configurations is the decoder fuzz and closest-location tests, which are `#ifndef _DEBUG`.
- Version stamps agree at `1.27.1` across `src/app.cpp`, `src/platform_win_res.rc`, `src/platform_win.manifest`, `installer/diff.nsi` and `exe/AppxManifest.xml`. The build number is raised by the packaging step, so the shipped build is one above the number in the tree.
- New tests for this release's fixes: an unreadable sidecar is refused rather than rebuilt, concurrent launches are not counted as failed ones, a saved window is brought back onto an attached display, a run resolves its rows by identity rather than by position, the row being worked on survives a reorder and comes to rest clear of the view's chrome, a selection panel with no detail form centres whatever the verbose toggle says, and a JPEG encoder is still usable after an encode is abandoned part way. Each was verified discriminating by breaking the rule and re-running.
- Not run before release: the categories listed in [post-release context](v-next.md#12-validation-not-run-before-release) are carried forward, together with this release's own manual gates — video with `-no-gpu`, sustained scrolling on a large collection, and the fresh install / update / uninstall pass.
