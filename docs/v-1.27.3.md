# Diffractor 1.27.3

Baseline: 1.27.2.

**Status: planning.** This document is the plan for 1.27.3. Nothing here is committed to until it
appears under [Changes](#changes) with a verification entry. GitHub issues remain authoritative for
issue state and discussion; the linked documents own the durable behaviour. Deferred work with no
release attached, issues awaiting reporter confirmation, and validation still to run belong in
[post-release context](v-next.md), not here.

1.27.3 has one subject: **a Linux user can see a window.**

It held four. Three of them — the date vocabulary, the sidebar globe, and the verbose metadata pane
— were built during 1.27.2 and are recorded there. Panorama display was pulled forward into 1.27.2
as well, because it needs a scan-time attribute on every indexed image and 1.27.2 already re-reads
every file for the date pack; asking users to sit through a second full re-index one release later
was not a reasonable thing to do to them. See [1.27.2](v-1.27.2.md).

What is left is the one subject that was never going to fit beside them, and it is better alone: a
release introducing a Linux window on the same commit as a build system carrying a shipped product
for the first time would put two new things in one failure path.

## Planned

### Linux support, stages 2 and 3

**Owned by [Linux port](linux.md).**

1.27.2 completed [Stage 0 and Stage 1](linux.md#staged-plan): the boundary is provable, the portable
core passes its whole suite on a second toolchain, and the CPU rasterizer, its present seam and the
backend interface are all portable. What is left before a Linux user can see anything is a window
and text, and those two are a single deliverable rather than two — neither alone puts a usable
picture on screen.

The order is forced by a dependency the staging does not make obvious: **[Stage 3](linux.md#staged-plan)
comes before [Stage 2](linux.md#staged-plan)**, because DirectWrite is now the only thing holding
`software_draw_context` on Windows. Text first, then the window that presents it.

- **[Stage 3, text](linux.md#the-text-stack).** FreeType, HarfBuzz and fontconfig behind
  `measure_context` and `text_layout`, on Linux only — Windows keeps DirectWrite, and
  [the reasoning](linux.md#the-text-stack) is recorded as decision 9. This is new code rather than a
  refactor, and it carries the port's one genuine layout risk: two shapers means two sets of
  advances, so a string can wrap differently on the two platforms.
- **[Stage 2, pixels](linux.md#staged-plan).** A window that owns a BGRA buffer and satisfies
  `ui::software_present_target`. Its gate is already executable and green —
  `Should rasterise one scene to one answer on every platform` compares the two platforms'
  rasterizers today.
- **[Stage 4, input](linux.md#staged-plan)** and beyond are not in scope for 1.27.3 and are listed in
  [linux.md](linux.md#staged-plan) rather than here.

One dependency is already paid: the segmented date control 1.27.2 introduces replaced the single
platform date picker in the UI, so nothing in the date path needs a Linux equivalent invented for
it.

Nothing in this subject changes Windows behaviour. If any of it does, it is a defect rather than a
feature.
