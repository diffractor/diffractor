# Diffractor 1.27.2

Baseline: 1.27.1. This release is `1.27.2`; the build number is raised by the packaging step, so the shipped build is one above the number in the tree.

This document lists what 1.27.2 changed. GitHub issues are authoritative for issue state and discussion; the linked documents own the durable behaviour. Work deferred past this release, issues awaiting reporter confirmation, and validation still to run are recorded in [post-release context](v-next.md).

1.27.2 carries the CMake build migration, stage one of the Linux port, the date vocabulary, the sidebar globe, the verbose metadata pane, and a set of view changes answering reported issues. It is a large release, so each subject lands with its own verification and can be attributed on its own.

## Overview

- **Three dates, and each says where it came from.** Original, Created and Modified are three first-class dates rather than one field carrying two meanings, each groupable, sortable and searchable, and the properties panel names the tag behind each. One resolver replaces four that disagreed, so an item can no longer group under one day and be found under another. An editor's save no longer moves a photograph to the day it was retouched ([#184](https://github.com/diffractor/diffractor/issues/184)).
- **`taken:`, `when:`, `timeline:` and `c:` now mean Original, and `created:` is narrower.** A saved search using any of them returns a different set, deliberately: those words never meant the container's date, and `created:` and `original:` had parsed to the same term, so one file listed under two months. Anyone who chose *group by date created* is moved to Original once. The upgrade re-indexes in the background and keeps answering throughout.
- **A wide panorama is something you can look around, and a declared sphere is somewhere you stand.** A merely wide picture zooms straight to 100% and the pointer sweeps its whole width, instead of the first stop above fit still being nothing to read. A file declaring `GPano:ProjectionType` of `equirectangular` is reprojected instead: the user turns a camera by dragging, and the ladder becomes a field of view in degrees. `@panorama` finds the ones that say so.
- **The items view carries its own settings.** The back-to-top button in the scroller track is the one control always on screen: hovering says what the listing holds and how much a filter is hiding, and clicking opens Group by, Sort by, the media-type filter and *Show items in subfolders* ([discussion #251](https://github.com/diffractor/diffractor/discussions/251)).
- **A region you draw on the picture stays.** `Ctrl` and drag draws a rectangle; it can be moved, zoomed to, or handed to Edit as the crop. It used to vanish the instant the button was released.
- **The selection panel and the media overlay each answer one question.** A container's stream summary is in the panel's first block rather than behind verbose metadata, a long description is bounded instead of evicting whatever followed it, and the overlay identifies the media rather than growing over the picture.
- **A picture is never stretched into the shape of the pane.** A camera's padded embedded thumbnail was distorted by up to a third until the real decode landed, which read as a compare-mode defect.
- **The cursor stays where you were working.** Moving files no longer resets the listing to the top ([#250](https://github.com/diffractor/diffractor/issues/250)), and a move refreshes the listing even with *Open folder after moving* off ([#249](https://github.com/diffractor/diffractor/issues/249)).
- **The sidebar map is a globe**, turned by dragging in both axes, and the file-type pie and history calendar are solids. The history chart gained a navigator band reaching the whole span of the collection. The indexed-folders section is gone, along with its Customise checkbox — a user will notice this.
- **Verbose metadata reports what the file holds**: unnamed tags kept, invented ones gone, the maker note as a directory for eight makes, a `Derived` section, the images a Multi-Picture JPEG indexes, and the embedded thumbnail as a picture.
- **Every icon is drawn from a font the product is allowed to ship.** Segoe MDL2 was embedded in every binary despite a licence that forbids redistribution; Fluent UI System Icons replaces it, so every glyph in the application is redrawn. A user will notice this.
- **Five vendored libraries were upgraded**, two of them for security: expat 2.8.3 ([CVE-2026-72522](https://nvd.nist.gov/vuln/detail/CVE-2026-72522)), libopenmpt 0.8.9, plus libarchive 3.8.9, libebml 1.4.7 and sqlite 3.53.4. **The binary also reports the licence the product is actually under**, which costs eleven game-console audio decoders and nothing else.
- **Renaming a set onto its own names works.** A numbered template used a second time over the same folder asked for names the same set was giving up, and Rename called every one a collision: each new name red, Run dimmed, nothing said about why.
- **One build description, on both platforms.** `df.sln` and the 26 vendored project files are gone, CI builds every shipping Windows configuration for the first time, and the portable core passes its whole suite under GCC.
- **A very large JPEG no longer draws green**, the duplicate badge appears only where there is a duplicate ([#137](https://github.com/diffractor/diffractor/issues/137)), and a completed path containing spaces reads as one term ([#139](https://github.com/diffractor/diffractor/issues/139)).

## Changes

### Three dates, and the tag each came from

**Owned by [design](design.md) and [metadata](metadata.md#dates).** Scope: all scopes.

**Original** (when the content was made), **Created** (when the file was made) and **Modified** (when it last changed) are three first-class dates instead of one field carrying two meanings. Each is groupable, sortable and searchable, and the properties panel names the tag each came from. One resolver replaces four that disagreed, so an item can no longer group under one day and be found under another — the "click to open finds nothing" report. A date pack stores every date a file carries grouped by value, with a bitmask naming the tags behind each.

`photoshop:DateCreated` no longer overwrites the shutter: it is the tag an editor rewrites on save, so it ranks last among capture sources and never moves a photograph to the day it was retouched ([#184](https://github.com/diffractor/diffractor/issues/184)). `EXIF DateTime` is read as a modification date, which is what the standard defines it as.

Two changes reach existing users, both deliberate:

- **`taken:`, `when:`, `timeline:` and `c:` now mean Original**, not the container's date. A saved `taken:2019` returns a different set. The words never meant the container's date, so this is a correction — but it changes results silently, which is why it is stated rather than discovered.
- **`created:` is narrower, and `original:` is the word for the other question.** The two had parsed to the same term, so a file whose Original is May and whose Created is August listed under both months. `created:` is now the Created concept alone, whose fallback is the filesystem stamp, and `original:` is the capture-first ladder the tile shows. A saved `created:2019` therefore returns a narrower set. `digitized:` is a spelling of `created:` rather than a fourth date, and `with:` no longer offers `digitized` or `date.pack`.
- **Anyone who chose "group by date created" is moved to Original, once.** That is what they believed they were choosing. The migration runs on the first start after upgrade and stops, so both orders stay separate and persist.

**The upgrade re-indexes in the background and keeps answering.** The database metadata version goes to 3; cached properties are kept and only the scan stamp is cleared, so search, grouping and the timeline answer from the legacy values until the incremental scan reaches each file. Thumbnails are untouched.

**It is also the last re-index the date model should ever ask for, and a rollback is survivable.** The stored pack states how long a group record and its trailer are, so a later release can append a field to either and every earlier build still reads the dates rather than discarding them; the source mask is 64 bits, of which 21 are used, so naming a new tag can never change the stored layout. Rolling a release back is ordinary, and both the cache and the settings are shared with whatever version is rolled back to: each row also carries the two date properties a pre-pack build reads, ahead of the record the oldest reader stops at; a cache stamped by a newer build has its stamp brought back down, so going forward again does not skip the upgrade it owed; and the new *Original* group and sort orders are stored under a value an older build understands as well as under their own. Without those, a rollback would date every file from the filesystem and silently drop the order the upgrade had just chosen. [metadata](metadata.md#the-date-pack) owns the cache side.

**Every rung of the ladder a scan can fill is filled, including the ones nothing reads yet** — a re-index is paid for by re-reading every file, so anything the table names is read now. IPTC `DateCreated`/`TimeCreated` and `DigitalCreationDate`/`Time`, ID3 `TDOR` and `TORY`, and `GPSDateStamp`+`GPSTimeStamp` were reserved but dead. So were the three pairs qualifying an EXIF date rather than being one: `OffsetTime*` and `SubSecTime*`. The zone changes nothing displayed — an EXIF date is already a wall clock — but it is half of recovering a zone a file never stated, and the GPS instant is the other half. The fraction keeps two frames of a burst apart. The two filesystem rungs are ranked and not filled, because those stamps live on the index record and change without a rescan; [metadata](metadata.md#dates) owns that.

### Every date says which tag it came from

**Owned by [design](design.md) and [metadata](metadata.md#dates).** Scope: all scopes.

Three dates were shown without saying where any of them came from, which leaves "the date is wrong" a question with no visible answer — the difficulty of [#184](https://github.com/diffractor/diffractor/issues/184).

- **The date bubble is four columns** — name, date, time, source — with the source dimmed, because it is provenance rather than value. Original, Created and Modified in a fixed order, then the filesystem stamps, and a stamp that already answered one of the three no longer appears a second time under its own name. An absent date omits its row. Every row is a wall clock: the index holds the two filesystem stamps as instants, so they are converted rather than listed beside the metadata dates in a different time.
- **Adjust dates names the date it changes and the tag each item resolves it from.** A set where one file is dated by its shutter and another by the day it landed on this disk is not a set the same shift means the same thing to, and that is now visible before the run rather than after it.
- **Adjust dates no longer rewrites the filesystem creation stamp.** Shifting a camera clock by two hours says nothing about when the file was written.
- **The metadata editor's date field is labelled Original**, which is the date it has always written, with Created and Modified reported read-only beside it and their sources named. They are stated only where the whole selection agrees; a single line claiming one value for a set holding several would be worse than saying nothing.
- **The sidebar timeline and the search its cells run are held together by a test**, not by both happening to call the same resolver. Clicking a month is the place a user is most likely to click, and a chart that bucketed an item under one date while the search answered with another would be "click to open finds nothing" at exactly that place.

### `original:` and `created:` are two questions

**Owned by [design](design.md#navigation-and-search) and [metadata](metadata.md#dates).** Scope: Search.

The two words parsed to the same term, so a file whose Original is May and whose Created is August listed under both months, and a day header asked for the union of both keys rather than for its own.

`original:` is the capture-first ladder the tile shows and Group by Date Original keys on. `created:` is the Created concept, whose fallback is the filesystem stamp. Each of the three date orders now draws its header from the key it groups by and asks for that same key, so a header lists exactly the items its cell counted.

The surfaces reading the capture-first ladder were moved onto it together — the sidebar calendar, the timeline visits, the group headers and the tile — so what a user clicks and what they get back are the same key. The properties and comparison tables label that ladder *Original*, which is the date they were already showing. The advanced search dialog gained the Original axis it was missing, and `with:` no longer offers `digitized` or `date.pack`: one is the old spelling of Created and the other is storage, and offering either teaches a fourth date that does not exist.

**A saved `created:2019` therefore returns a narrower set.** The words never meant each other, so this is a correction — but like the `taken:` change above it alters results silently, which is why it is stated here rather than left to be discovered.

### A picture wide enough to look around

**Owned by [zoom](zoom.md#62-looking-around-a-wide-picture) and [design](design.md); the attribute by [metadata](metadata.md#panorama).** Scope: all scopes.

Fitted to a browsing window a 12000x1000 stitch is a bright line, and the ladder's first stop above fit is still nothing to read.

- **`GPano` qualifies a file outright.** Failing that, an aspect ratio of at least 2:1 **and** a long edge of at least 4000 pixels. Both are stored dimensions, so the shape test costs no field and can be retuned without a re-index. Aspect alone would claim every wide screenshot; the size floor excludes them. `@panorama` still finds the declaration alone, because a search is an assertion about the file rather than about how it is drawn.
- **Zooming a picture that qualifies by shape goes straight to 100%**, where the strip is legible.
- **The pointer then drives the centre**, so crossing the viewport sweeps the whole width. No button is held, so press-and-hold [inspect zoom](zoom.md#21-two-magnified-states-one-zoom) is untouched and no layer is added for `Escape` to peel.
- **Vertical is pinned unless there is something to see.** Taller than the viewport at that scale, the pointer drives it too; otherwise it is fixed, because following the pointer with nowhere to go is only jitter.

A file that declares a sphere is not merely wide, and gets the treatment below instead.

### A file that declares a sphere gets one

**Owned by [zoom](zoom.md#64-standing-inside-an-equirectangular-panorama) and [rendering](rendering.md#a-projected-panorama); which patch of the sphere a file claims by [metadata](metadata.md#which-patch-of-the-sphere).** Scope: all scopes.

An equirectangular file is a sphere unrolled onto a rectangle. Drawn flat its horizon bows and its verticals lean, and the wider the field the worse it gets — so magnifying one now puts the user inside it rather than along it.

- **`GPano:ProjectionType` of `equirectangular` qualifies a file, and nothing else does.** `cylindrical` names no vertical mapping the writers agree on and `unspecified` names no projection at all, so both keep the flat treatment above. Shape never qualifies a file for this: reprojecting a picture that merely looks wide would bend one that was never bent.
- **The picture is reprojected through a camera the user turns by dragging**, and it opens facing the middle of what the file actually holds. A held pointer aims, as inspect zoom already does on a rectangle; a free drag turns the world by exactly one field of view per viewport crossed, so the gesture feels the same at every stop. It replaces the pointer sweep above rather than adding to it, because one picture must not answer the same movement twice.
- **Scale becomes a field of view**, from 120° down to 9°, and the readout says degrees — there is no pixel inside a sphere to be one-to-one with. Stepping out from the widest stop leaves the projection, and asking for `100%` leaves it too, rather than quietly redefining what that command means.
- **A partial panorama ends.** Most phone panoramas cover a band rather than a whole sphere, and where the file holds nothing the frame shows nothing — not the nearest row stretched, and not the sky invented. The declaration is read from the file when it is displayed, so no collection needs re-indexing to gain this.
- **The user can ask for the flat pixels.** Judging a stitching seam means seeing what is stored, so a control in the zoom chrome switches between the two and says which is in force. It is per item, because it is a judgement about one picture.
- **Both backends show the same picture.** The GPU projects it with a shader; where there is none — the CPU renderer, or a device that has been lost — the same frame is rasterised in software. The camera and the coverage rule are derived once and shared, so no pixel comes from a different place because of the backend; hardware sampling is sharper at a glancing angle, which is a difference in filtering rather than in what is shown.

### The items view carries its own settings

**Owned by [design](design.md#application-structure).** Scope: Indexed collection, Folder, Recursive folder, External folder, Search.

[Discussion #251](https://github.com/diffractor/diffractor/discussions/251): the filter toolbar at the top of the thumbnail window scrolls away, so changing a filter over a long listing meant scrolling to the top first — and *Show items in subfolders* was not on it at all.

Pinning that toolbar spends vertical space permanently, in the view whose entire purpose is showing thumbnails. **The control that is already always on screen carries the settings instead.** The back-to-top button in the scroller track is sticky by construction, so nothing has to be pinned.

- **Hovering shows what the listing holds**, broken down by file type, and — when a filter is hiding anything — how many. That last number is the one a user needs *before* opening the filter menu.
- **Clicking opens a menu** carrying Group by, Sort by, the media-type filter, Show items in subfolders, and Scroll to top.
- **The click opens the menu in every scroll position.** Scrolling when scrolled and opening a menu when not would be a context-dependent surprise, so scrolling to the top is the menu's first entry and the button keeps the dimming that already said whether it had anything to do.
- **Every other entry is the toolbar's own command**, so the two copies cannot disagree about what is offered, enabled or ticked. The test compares them by identity rather than by name.

### The panel and the overlay each answer one question

**Owned by [selection controls](selection-controls.md) and [design](design.md#application-structure).** Scope: all scopes.

- **What is inside a container is a media file's first question**, so the stream summary is part of the panel's primary block rather than something to open verbose metadata to reach. Answering it below the fold was not answering it.
- **A description is bounded.** Prose has no natural end, and an unbounded one took the panel and evicted whatever followed it — which is how the stream summary came to be the thing that went. Past a few lines it collapses to a row that opens on demand.
- **The media overlay identifies rather than summarises.** It grew with whatever metadata it found and overflowed the picture, competing with the only thing the Media view exists for. A photograph or a video is already on screen, so its name, date, rating and label are the whole of what the overlay adds. Audio is the exception: the media is not a picture, so the overlay *is* the presentation and title, artist, album and track stay.
- **The invariant that stops it returning: never more than a quarter of the media's height** — a half for audio, where the panel *is* the presentation — truncating rather than growing. It is a fraction rather than a number of pixels, so it holds at every scaling, and it is asserted as a measurement rather than judged by eye. A floor below both fractions keeps the identification readable in a window too small for either to hold anything.

### A region on the displayed picture

**Owned by [zoom](zoom.md#63-a-region-drawn-on-the-picture) and [design](design.md#application-structure).** Scope: the media preview in the Items view, in every scope.

`Ctrl` and drag draws a rectangle on the picture; dragging inside moves it; `Escape` clears it. It carries three icon buttons: close, **zoom to it**, and **open Edit with it as the crop**.

- **It lives in source space**, so it survives a resize, a layout change and a zoom, for the same reason the [zoom model](zoom.md#2-the-model) keeps its centre there. A rectangle that slid off the subject would be worse than none.
- **It is clamped to the picture** rather than naming pixels that are not there, and a drag that runs backwards is still a rectangle.
- **It does not outlive the item.** A crop region is about one picture, so it is held keyed to the item rather than on the panel that draws it — that panel is rebuilt for anything from a sidecar arriving to index progress, and a background update must not erase what the user just drew.
- **The buttons are hidden during a drag**, and sit outside the rectangle when it is too small to hold them, clamped into the pane so a rectangle at the edge is still something to act on rather than something to redraw larger first.
- **`Escape` peels one layer** ([L5](zoom.md#3-the-laws)): with a rectangle it clears it, without one it falls through to the unwind ladder that already existed. It does so in the Media view as well as in Items, because a region can be drawn in both.
- **The zoom chrome keeps its precedence.** The region's own three buttons answer first, but the zoom tools and the navigator answer before the rectangle body, so a rectangle drawn across them does not make them unclickable.
- Zoom-to is the same region-to-viewport primitive `Ctrl` and drag used to perform outright; open-in-Edit maps the same rectangle onto the stored pixel grid the crop is expressed in, which for a rotated capture is not the space it was drawn in. Neither is a new model.

**`Ctrl` and drag no longer zooms on release.** It drew a rectangle that vanished the instant it was let go, so the only thing it could do was the one thing it did. The rectangle now stays, and zooming to it is one of three things it offers. Compare mode keeps the transient gesture, because a region belongs to one picture.

### A date is typed rather than picked

**No owning document yet: the model is [ui_date_edit.h](../src/ui_date_edit.h), and 1.27.3 owns drawing it.** No observable behaviour change.

The model that replaces the Windows date picker is here: segment order taken from the display locale, digits typed left to right with the field advancing by itself, and stepping that applies one unit of the active segment to the whole date — so 23:59:59 rolls into the next day and December into January of the next year, because that is what a clock does. A month or year step clamps the day the new month does not have, so 31 January steps to the end of February rather than to a date that does not exist.

Nothing draws it yet, and `ui::date_control` still creates the platform picker. Drawing it is [1.27.3's](v-1.27.3.md#one-date-control-and-it-is-ours).

### A picture is never stretched into the shape of the pane

**Owned by [rendering](rendering.md#a-stand-in-is-fitted-never-stretched).** Scope: all scopes.

A pane is laid out for the shape the item *is* — the indexed dimensions, known long before any pixels arrive. What gets drawn into it is whatever the display ladder has reached, and the first rung is the item's thumbnail. A thumbnail Diffractor generated is a downscale and matches to within rounding, but an **embedded thumbnail is stored verbatim**, and cameras routinely write a padded 160x120 for a 3:2 or 16:9 frame. Stretching that into the pane is a 12 to 33 per cent distortion until the decode lands.

**The picture is now fitted inside the pane rather than stretched to fill it.** An aspect that already agrees is left exactly where it was, to within one device pixel, so no correctly shaped image moves and nothing acquires bars from a rounding difference. The pane itself does not move: publishing the stand-in's shape as the item's would have jumped the layout the moment the real image arrived.

### The cursor lands where the files left

**Owned by [design](design.md#guided-operations).** Scope: Folder, Recursive folder, External folder, Search.

Moving files reset the cursor to the start of the listing, which turns sorting a folder into a re-navigation after every action ([#250](https://github.com/diffractor/diffractor/issues/250)). It now settles on the item that followed the set that left — and, where the set ran to the end of the listing and nothing follows it, on the item that preceded it, because jumping to the top is the same reset whether the set was in the middle or at the end. The rule is shared with delete rather than re-derived, so both land in the same place. With *Open folder after moving* disabled the move also re-runs the listing from its own completion rather than only when the queued re-enumeration happens to notice the folder changed ([#249](https://github.com/diffractor/diffractor/issues/249)). Neither changes what a move does to a file or touches the recovery contract in [file I/O](file-io.md).

### The ping says what the machine is

**Owned by [design](design.md#what-the-daily-report-says-and-what-it-may-not).** No observable behaviour change.

The daily ping reported version, build, first run, features used, run count and an OS string that is `"10.0"`, `"11.0"` or the bare word `"Linux"`. It could not answer *"can I stop shipping 32-bit Windows?"*, because architecture was not reported at all.

A single parameter **`s`**, a `uint64` in hex, carries platform identity: layout version, OS family, a coarse OS version, the process architecture, the **native** machine architecture, and the package the build was installed from. It ships *alongside* the old OS string for one release so the ingest can change without a gap in the daily series. What may be in it, how it is encoded and why, and what its numbers can and cannot say are [design's](design.md#what-the-daily-report-says-and-what-it-may-not).

### A file that says it is a panorama

**Owned by [metadata](metadata.md#panorama).** Scope: all scopes.

The scan records the projection a file declares in Google's `GPano` namespace, and **`@panorama`** (short: `@pano`) finds them. Panoramas were unfindable: they look like photographs to every query. It rides the date re-index rather than asking for one of its own, because a per-image attribute costs a full re-read and asking for a second pass would be unreasonable. The projection is stored rather than a yes/no — it is the same byte, and it is what decides whether magnifying a file stands the user inside it, above. The declaration only, never the shape.

### The sidebar is a globe and a set of solids

**Owned by [locations](locations.md#50-the-sidebar-globe) and [rendering](rendering.md#the-sidebar-globe).** Scope: all scopes.

The flat world map is a sphere at the same size, turned by dragging in both axes and framed on the collection's own places; the hover bubble, place-plus-radius click and grouping guarantee are unchanged. The file-type pie and history calendar are extruded solids from the same rasteriser, each recording what every pixel shows so the pointer matches the silhouette rather than the geometry.

**The history chart is one control in two bands.** Eight years of month blocks is what the eye takes in at once, and under them a navigator holds the whole plausible span of the collection, one bar per year. The navigator is how a user reaches the rest, and how they see where in time their photographs actually are before they go looking — which is what [#175](https://github.com/diffractor/diffractor/issues/175) reported as older years missing. The *History chart start year* setting is now the earliest year the navigator offers rather than the size of the window, and left empty it is worked out from the collection.

**The indexed-folders section is gone**, with its Customise checkbox and setting. A collection's folders are how it was declared, not a row apiece, and a folder a user wants to hand is a saved search away. A user will notice this, which is why it is stated here.

### Verbose metadata reports what the file holds

**Owned by [selection controls](selection-controls.md#verbose-metadata-blocks).** Scope: all scopes.

Two libexif defaults were editing what the block inspector showed, and three kinds of content it held were never presented.

- **Nothing is dropped and nothing is invented.** libexif discarded unnamed tags and supplied mandatory ones a directory omits; both are cleared, so an unknown tag is listed under its number and a directory reports what the file stored. The same default rewrote off-spec entries, so a value stored as `LONG` where the standard says `SHORT` reported a synthesised dump; the file's own format and bytes are shown. Write paths keep both defaults, because a file being produced should conform.
- **The maker note is a directory, not a blob** — Canon, Nikon, Fuji, Olympus, Sanyo, Epson, Pentax and Casio, in a section named for the make.
- **A `Derived` section** carries crop factor, angle of view, circle of confusion, hyperfocal distance, light value and megapixels, each only when every tag it needs is present.
- **A Multi-Picture JPEG lists the images it indexes**, with the role and extent each declares.
- **An embedded thumbnail is shown as a picture**, at its own size unless the pane is narrower, open without being asked. A hex dump is the fallback for what cannot be decoded, and never opens unasked. Decoding happens where the block is built, never while painting.

Two defects fixed alongside: a crafted Multi-Picture segment could read outside the buffer, because file-supplied 32-bit offsets were bounds-checked in 32-bit arithmetic; and a set of elements held a texture belonging to a lost graphics device — `cover_art_control`, the embedded thumbnail inside a metadata block, and the sidebar's globe, pie and calendar, which were never reached by the broadcast at all. After a device is lost or the renderer falls back to the CPU, each of those drew nothing for the rest of the session.

### One build, on both platforms

**Owned by [Linux port](linux.md#retiring-msbuild).** No observable behaviour change.

`df.sln`, `src/app.vcxproj` and the 26 vendored `.vcxproj` files are gone. CMake is the only description of the tree on both platforms, and the lint fails a tracked `.sln` or `.vcxproj` so a second cannot return quietly. The two builds compiled the same translation units and agreed on every define; the differences are recorded in [tools/build-divergence.txt](../tools/build-divergence.txt), including the SSE2 baseline, which is unchanged. The last FFmpeg switch the two disagreed on was `--enable-gpl`, closed by the licence change under [what the binary carries](#what-the-binary-carries). Windows CI now builds Debug and Release x64, Release Win32 and the Store binary and runs the suite on each — none of which had ever been built by CI. The FFmpeg and XMP forks are no longer optional: without them the application reports every media file and every XMP property as absent.

### Linux support, stage one

**Owned by [Linux port](linux.md).**

The portable core builds and passes its whole suite under GCC 13 in both configurations, all 26 vendored libraries build, and [linux.yml](../.github/workflows/linux.yml) guards it. Path identity now follows the filesystem as a compile-time property, case-sensitive off Windows and unchanged on it. `wchar_t` is no longer assumed to be UTF-16 and `std::wstring` is out of the platform interface. The CPU rasterizer is portable code behind a present-target interface, and the two platforms' rendering is compared against recorded pixels rather than assumed to agree. D3D11VA is out of the media layer.

**Two changes reach Windows, and the first one is visible everywhere.**

- **Every icon is drawn from a font the product is allowed to ship.** Segoe MDL2 Assets is a Windows system font whose licence forbids redistribution, and it was checked in and embedded in every shipped binary. [Fluent UI System Icons](https://github.com/microsoft/fluentui-system-icons) replaces it on both platforms, so every command, toolbar and status glyph on Windows is now a different typeface, drawn at an em raised by a tenth to match the old ink height. It also resolved three glyph collisions — Cut and Copy shared one code point and drew identically — and a handful of icons have no exact counterpart and were reassigned. Which ones, and how the set is regenerated after a font upgrade, are [Linux port](linux.md)'s.
- **`platform::image_to_surface` is gone from the interface**, so GIF, BMP, TIFF, TGA, SGI, the PPM family, DPX, PSD, PCX, XBM, SUNRAST and QDRAW are decoded by the media layer rather than by WIC on Windows too. The decoders differ, so what those formats look like can differ. `.cin` has no decoder either way.

There is no Linux window, renderer, desktop integration or packaging; everything in [features with no Linux equivalent](linux.md#features-with-no-linux-equivalent) is untouched.

### What the binary carries

**Owned by [third-party](third-party.md).**

- **Five vendored libraries were upgraded, two of them for security.** expat 2.8.2 to 2.8.3 ([CVE-2026-72522](https://nvd.nist.gov/vuln/detail/CVE-2026-72522)), libopenmpt 0.8.7 to 0.8.9 (two security releases), libarchive 3.8.8 to 3.8.9, libebml 1.4.6 to 1.4.7 and sqlite 3.53.3 to 3.53.4. FFmpeg is not upgraded; it is reconfigured, below. The integration patches each tree needs, and what an upstream copy adds and omits, are recorded in [third-party](third-party.md).
- **The binary reports the licence the product is under.** Every source file in `src/` says LGPL 2.1 or later while the Windows FFmpeg build reported *GPL version 2 or later*. Both platforms now configure LGPL, and the Linux build never passed `--enable-gpl`, so this also closes the last configuration difference between them. It costs eleven components, all game-console audio found inside FMV and ROM containers: eight ADPCM decoders and the CRI AHX decoder, parser and bitstream filter. No video codec, image decoder, demuxer or hardware acceleration is affected. Which eleven, and what a regenerated config must re-zero so a rebase cannot reinstate them, are [third-party](third-party.md)'s.
- **The Linux build now carries what the Windows one always did.** `--disable-autodetect` had silently taken thirty decoders off it — APNG, EXR, TSCC, ZMBV and the screen-capture family among them — and tracked music with them; and it was building encoders and muxers nothing reads, which cost 65 MB. Windows reads a checked-in FFmpeg configuration and had none of those differences, so nothing in *this* bullet changes what a Windows user can open; the eleven that do are named above. This is the two builds agreeing, which is the point of there being one build description.

### Smaller changes

- **Renaming a set onto its own names works.** A numbered template used a second time over the same folder asks for names the same set is giving up, and Rename called every one of them a collision: each new name red, Run dimmed, and nothing said about why. Those names are recognised as free, because the run empties them before they are taken; a skipped row returns the name it kept to whatever was waiting on it; and a dimmed Run names its cause. **Owned by [design](design.md#guided-operations).**
- **Go to parent folder sits with Back and Forward**, and draws a plain up arrow rather than a folder with an arrow, which read as something done to a folder. **Owned by [design](design.md#application-structure).**
- **The date direction is one option, not a sort key.** *Sort dates descending* and *ascending* were two items expressing one yes/no choice, so one was always ticked and clicking it did nothing. There is now one item, **Show newest items first**, below the sort keys, naming an outcome a user can check against the screen. **Owned by [design](design.md#command-availability).**
- **An edge between the address bar and the surface that scrolls.** They shared a background, so it was not obvious which part scrolled. The line is drawn over the view's top row rather than taking space from it.
- **A very large JPEG no longer draws green.** At the ladder's smallest scale a 4:2:2 or 4:4:4 image averaged two chroma rows from a buffer holding one, indexing by position within the call rather than within the image, so half of every chroma sample came from memory nothing had written. 4:2:0 was never affected, which is why it followed particular files. **Owned by [file I/O](file-io.md#4-reading-the-display-phase-ladder).**
- **A video with non-square pixels is the right shape everywhere, not only in playback.** A broadcast-derived file declares its display shape in the container rather than in the bitstream, and that declaration reaches the stream and not the decoded frame — so a file whose bitstream states no aspect ratio of its own handed the thumbnail decoder a square-pixel frame the container contradicted. Playback was right while the thumbnail and the timeline hover preview stayed at the stored shape, which is why the file looked correct the moment it was opened and wrong everywhere it was listed ([#78](https://github.com/diffractor/diffractor/issues/78)). **Owned by [rendering](rendering.md).**
- **Fixed and confirmed by the reporter:** ratings and labels on a network drive ([#207](https://github.com/diffractor/diffractor/issues/207)), which risked silent data loss, and rating a photo no longer changing which date it groups under ([#192](https://github.com/diffractor/diffractor/issues/192)).
- **A sidebar timeline cell opens the items it counted.** The chart and the search its cells run are held together by a test rather than by both happening to call the same resolver. That is the other half of [#175](https://github.com/diffractor/diffractor/issues/175): the navigator above makes the older years reachable, and this makes the cell answer with the items it drew. **Owned by [design](design.md#navigation-and-search).**
- **The duplicate badge appears only where there is a duplicate.** It counted the copies the collection holds of a file, this one included, so it read "1" on every file that has no duplicate at all — a number true of everything, which the reader had to learn before they could ignore it ([#137](https://github.com/diffractor/diffractor/issues/137)). **Owned by [collections](collections.md).**
- **A recursive folder scope stops at a folder boundary.** *Include items in subfolders* over `C:\Pics` also claimed `C:\Pictures`, because the two were compared as text with no separator between the root and what follows it. A scope silently holding files the user never pointed at is the worst kind: everything it reports is true of some file, just not of the ones asked for. **Owned by [design](design.md#navigation-and-search).**
- **Every group header opens the items it counted.** A day header is only worth clicking if the search behind it answers with the set that drew it, so each of the three date orders answers from the same rungs its header is keyed on — including the filesystem stamp a file with no creation tag falls back to, and including the local reading rather than the stored instant. Original is also in the order `Alt+Down` cycles and carries *Show newest items first*, so the order the upgrade moves people onto is not the one order missing its affordances. **Owned by [design](design.md#navigation-and-search).**
- **Sync refuses two folders when one is a drive root containing the other.** The overlap guard compared the two as text and a root keeps its separator, so `C:\` was found to contain nothing and Sync would run a folder into its own subtree. **Owned by [design](design.md#guided-operations).**
- **A completed path containing spaces reads as one term.** Typing a path was already quoted; committing one from the completion list after another term was not, so `C:\My Photos` parsed as two ([#139](https://github.com/diffractor/diffractor/issues/139)). Both now apply the same rule rather than each carrying its own. **Owned by [design](design.md#navigation-and-search).**
