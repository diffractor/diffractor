# Diffractor 1.27.0 Release Plan

Baseline: 1.26.4, released 2026-07-02 as build `1.26.4.1215`.

GitHub issues are authoritative for issue state and discussion. This document is the 1.27.0 release contract: included changes, verification evidence, and remaining gates.

## Included changes

- **Metadata and file safety**: #3, #22, #65, #103, #117, #123, #180, #184, #207, #230, #231. Includes authoritative XMP tag deletion, MP4/MOV `Xtra` and ASF interoperability, filtering binary Samsung JPEG comments, bounded failure for locked-file updates, OneDrive-visible modified dates, EXIF DateTimeOriginal precedence, `;`-separated multi-value genres, hardened SMB replacement and cleanup, additional embedded-XMP formats, and concrete write errors. The durable behavior these settled is owned by [file I/O](file-io.md).
- **Media and rendering**: #61, #78, #189, #214, #219, #232. Includes video locations on the sidebar map, sample-aspect-ratio display, GPU/software glyph-cache invalidation, aspect-ratio grouping, Korean tag/search and fallback-glyph handling, and caching failed font lookups.
- **Interaction and settings**: #58, #102, #105, #119, #135, #175, #178, #221, #227, #228, #229, #233. Includes distinct `with:`/`without:` search semantics, bracket-key rotation, sidebar resizing, localized location names, NumPad rating/labels, a configurable full-collection history span, preserved search input, optional autoplay, favorite-tag initialization, a blank tag action field, and persisted detail/thumbnail presentation and media filters.
- **Zoom**: the work specified in [zoom](zoom.md). Zoom becomes one model — a scale and a source-space center — shared by every input and both rendering backends, replacing the previous ad-hoc magnification. There are exactly two magnified states and two names for them: **inspect zoom**, the disposable press-and-hold peek, and **zoom mode**, durable until the user leaves it. Zoom mode has one direct entry, `Ctrl+Space`, and one exit, `Escape`, which peels a single layer per press and never closes the view while the image is still magnified. Because zoom mode hides the browsing chrome it also reduces the command vocabulary to operating the zoom, moving through the sequence with the page keys, and grading the image — rating, colour label, reject, and to do — with every other command an inert silent no-op. That grading vocabulary is shown, not hidden: a row of inline checkable controls sits bottom-right and reports the current value of everything zoom mode can change, and the same controls appear in the Items and fullscreen panels so the gesture is learned once. Fit is a calculated state that recalculates through resize, DPI change, and navigation. Adds fit variants, a fixed ladder with reversible stepping through `Fit`, pointer anchoring, a source-space center carried across images, linked comparison zoom, immersive layout, region zoom, nonlinear pan and auto-pan, a corner navigator that is a persistent interactive control in zoom mode and information-only during inspect zoom, precision wheel accumulation, touch pan/pinch/double-tap, and interactive-versus-settled sampling tiers that upgrade quality when the view settles. Decoded-image retention is bounded and adjacent images are prefetched. [zoom](zoom.md) §16.1 lists the parts of this still outstanding; §16.2 lists what is deliberately deferred beyond 1.27.0.
- **Locations and distance search**: the 1.27 work specified in [locations](locations.md). Places gain qualification levels and a single name composer, so one identity is used by headers, bubbles, and terms alike. Every location term resolves a place instead of matching a stored field, so `place:`, `city:`, `state:`, `country:`, `loc:`, and `near:` answer for GPS-only items. Attribution is bounded by a population-scaled radius, replacing confident wrong names with `Near X` or `Remote area` plus a bearing. Adds map clicks that emit the same readable radius-bearing `loc:` term a user could type, No-Results recovery offering Widen and drop-qualification, and a places breakdown. The shipped gazetteer is regenerated from a current GeoNames snapshot and deduplicated, and the breakdown chips are keyed and labelled so no two of them can read the same. The distance-slider and visit-timeline presentations and altitude-derived classes are deferred. Resolves baseline defects 1, 2, 3, 4, 5, 7, 8, 9, and 10.
- **Installer and shell**: #173, #215. Desktop shortcuts are created only on fresh install; the folder verb uses `Directory\shell`; uninstall removes legacy entries. The installer also replaces its own data files unconditionally rather than only when newer, so an update cannot keep a stale `location-places.txt` or translation catalog, and uninstall removes the Explorer per-extension Open With advertisement it created.
- **Selection panel**: the 1.27.0 scope in [selection controls](selection-controls.md#release-scope). Comparison is decided by a file-trait profile rather than by there being two items, so an image/video pair no longer gets a comparison table; presence has its own compare/count badge in singular and comparison, with detailed status and related items in its bubble rather than the title; Location, Tags, and Description close the singular panel and are stated even when empty, each with the affordance that opens its own task; the six-tag cap applies in both densities; and comparison rows render from whichever metadata snapshot has arrived. No new translatable strings.
- **Photo edit**: the Edit view gains perspective correction on both axes, temperature and tint, and three automatic adjustments — Auto color, Auto straighten, and Auto document. Preview compares the original against the edited result, and `Escape` peels one layer per press rather than discarding the edit. Editing another item from inside the view prompts before losing changes. Metadata editing has been removed from this view; tags, rating, and description belong to their own tasks per [design](design.md). One editable-photo test decides entry, the selector strip, and Save+Next/Back, so those three cannot disagree: navigation stays inside the photos the view can actually edit instead of stranding the user on a video, folder, or unsupported file. Each automatic adjustment analyses a decoded copy on a worker and applies its result only if the same photo is still displayed, so a large RAW file no longer stalls the window while it is scanned, and each states that it found nothing rather than appearing to do nothing. Auto document proposes its correction through the straighten, perspective, and crop controls the user already has rather than baking a rectified page: the image morphs, the crop stays a rectangle bounded to the page, and every value it chose is shown in the sliders so it can be fine tuned or undone one control at a time. Saving pixel edits to a format Diffractor cannot write asks for the destination, so an existing sibling JPEG — the usual RAW+JPEG case — is confirmed before it is replaced instead of being silently overwritten. Save options — keep an original backup, JPEG quality, WEBP quality, and WEBP lossless — now sit in a section under the color controls in the edit panel instead of behind a toolbar popup, and the panel opens with a sentence describing what the view does, matching the other task views; the `Change save options` command and its dialog are gone. Adds one translatable string and removes one, translated in all 13 catalogs.
- **Metadata editing and command clarity**: a command a user cannot run now says why, and the batch metadata surface offers the vocabulary each field actually accepts. Scale up defaults off and its help states the off behavior first, so the setting is no longer described only by what turning it on does. The unsupported-type message names the extension it is refusing and states that no sidecar is written for it, replacing a bare "cannot update metadata of this file type". The Edit tooltip describes pixel editing only, because metadata editing left that view. Grading and edit commands that fail whole-selection eligibility stay visible and dimmed, per [selection controls](selection-controls.md), and carry the same reason text the operation itself would report; Rate or Label is gated on the same test as the ratings and labels inside it, so the menu can no longer open onto commands that all fail. Genre is a picker filtered by the traits of the selected items and merged with the genres already in the collection, with an explainer that `;` separates multiple values. Rating is a star and Reject control bound to the pending batch value rather than a number spinner, so the batch field uses the same grading vocabulary as everywhere else. Eligibility is now decided by one spelling of the edit trait, with a regression test over a file group that declares no edit trait. Adds four translatable strings, translated in all 13 catalogs.
- **Pin**: pin is now present in the two panel forms that can compare. It appears in the singular viewing group and at the head of each comparison column, alongside Unselect and Delete as the three ways a comparison ends — keep this one, drop this one, destroy this one. It previously existed only in the singular non-media table, where comparison is impossible. The held item is marked in the items list in both detail and thumbnail presentations, so pin is visually distinct from selection as [design](design.md) requires. The command reports and releases the item it holds instead of silently moving the pin to whatever has focus, and unselecting one item no longer releases a pin held on another. A pin is released when its item stops being a visibly selected displayed item, so a search, a filter, or an inverted selection can no longer leave a pin the user cannot see. Specified in [selection controls](selection-controls.md#release-scope) item 6. No new translatable strings.
- **Guided file operations**: Rename, Import, and Sync follow Scope → Target → Options → Analyze → Review → Run → Results. Analysis runs off the UI thread from detached values, Run uses the reviewed immutable path plan, and each row is held to the files it named: Run revalidates that row alone, immediately before it acts, rather than re-deriving the whole plan first. A destination the review found free is proved free by the write itself, which closes the window in which it could appear; a destination being overwritten and a file being deleted must still match what was reviewed. A row that no longer matches writes nothing and is reported as failed, and the run states that files changed after analysis alongside its counts; the rows that still match still run, instead of one changed file anywhere discarding the whole run. Over a network share or a camera card this also removes a second full scan of both sides from Run. One collision policy applies to each primary file and its sidecars as a logical group; Block Run disables Run, Skip leaves originals, Replace is explicit, and Auto-rename uses one shared suffix. Cancellation classifies every unattempted row, Import records history only for fully successful logical items, and retained Results distinguish success, failure, ignored, and canceled rows. Import's Replace is the one policy here that destroys content with nothing to recover from, so Run states the count and its permanence before acting; that count is now the rows the plan will actually write, not every row whose destination happens to exist, so a previously imported file no longer inflates it. Adds one translatable string, translated in all 13 catalogs.
- **Copy and Move state their collisions**: both commands went through the shell with auto-rename forced on, so a destination that already existed was silently resolved to a second copy and a user who meant to replace had no way to say so. They now name the files already at the destination and offer Auto-rename or Replace, defaulting to Auto-rename because it destroys nothing, with Cancel as the third answer. The prompt uses the same named CollisionPolicy vocabulary as Import, Rename and Convert, offering only the choices that resolve a collision already found — Block Run would repeat the Cancel button beside it, and Skip is not expressible through the shell. The collision test reads the destination once instead of querying per item, so the count of selected files no longer decides how many network round trips happen before a modal opens. Paste and drag-drop still auto-rename, which is safe but unstated; see [post-release context](v-next.md). No new translatable strings.
- **Menu simplification**: each command now appears in one place. The media context menu no longer restates the zoom commands, the tools, and the playback toggles that its own submenus already hold; the zoom commands, including `Flip comparison panes` and the fit variants, are gathered under one `Zoom` submenu with the navigator display options nested beneath it as `Navigator`; the items context menu drops the entries duplicated from `Navigate` and `Display options`, and the playback submenu it did not need. There is now one definition of a tool, shared by the menu and the toolbar panel, with `Related items` among them, and one grouping list, shared the same way. The main menu's seven settings entries collapse into a single `Options` submenu. The unreachable pinned navigator option is removed. Popup menus now nest to more than one level, which the previous Windows menu builder silently flattened. Changes one translatable string and removes one, translated in all 13 catalogs.
- **Fullscreen and task views**: starting a task from fullscreen — Edit, Tags, Locate, Rename, or a metadata batch — now leaves fullscreen and keeps the item the task targets, instead of opening the task behind a hidden top bar with its toolbar invisible. Fullscreen was already refused from a task view; the two states now cannot coexist in either direction. No new translatable strings.
- **Slideshow feedback**: a running slideshow reports itself on the Slideshow control — checked, a pause icon, and a fill along its base showing how much of the current photo's delay has elapsed. The control is now shown for video and audio too, so the slideshow can be seen and stopped whatever it has landed on. The progress fill lost in an earlier refactor is restored on the control that ends the mode, rather than on Play, which is transport within one item and stops a slideshow when invoked. No new translatable strings.
- **Selection panel grouping**: the singular selection panel now reads as two groups split by the file, per [Selection controls](selection-controls.md). Viewing carries playback options, Slideshow, Pin, orientation, RAW preview, Scale up and Fullscreen; Actions carries reject/label, rating, rotate, Edit, Open and Tools. Rating and the label flag previously sat among the viewing icons while Slideshow sat among the file-changing actions, so neither row answered one question. Previous and Next are removed from the Selection summary panel, which has no single item to advance from. Fullscreen keeps camera, dimensions, album, and artist, which its compact budget had removed along with the file and encoding facts. No new translatable strings.
- **Command availability**: every command is now gated on the surface where its effect is visible and on whether its target qualifies, per [Command availability](design.md#command-availability). Sidebar, detail size, thumbnail size and large-item highlighting are offered in Items rather than also in Fullscreen where they change nothing; verbose metadata is offered in Fullscreen, where it does change what is drawn; Google Maps, Tools, Playback and the group-order toggle carry the gate their entries already had; the extend-selection browse commands require items to browse; and Close and Items are tested by view alone, so a running command no longer makes them available. No new translatable strings.
- **Eject**: the command now does what its own help promises.
 Ejecting locks and dismounts the volume before it removes it, so a drive still being written to is reported rather than torn away, and removal falls through to the device node — the only mechanism that removes a USB or external disk, which the media-eject IOCTL alone never could. Drive scanning and the eject itself run on a worker, so a slow or unresponsive drive no longer freezes the window. Each drive is listed as `Eject X:\` with its label, capacity, used space, and filesystem as labelled and translatable parts, omitting whatever the drive does not report; a failure is reported after the dialog has closed rather than from inside the running button, which previously destroyed the dialog it was drawn on; and a machine with no removable drive says so instead of offering nothing but Close. The command is available from every view, because ejecting a drive does not depend on what is being browsed. Adds one translatable string and removes one.
- **Collection comprehension**: the collection is now explained where the user meets it rather than assumed. About, Collection options, the indexing message, the in-collection and outside-collection reports, and the empty-search message state one idea in one vocabulary — the collection is the folders you choose including their subfolders, indexing them is what makes search, duplicate detection and totals cover everything at once, and changing that declaration changes only what Diffractor knows. The "no files are moved or copied" promise is scoped to the act of defining the collection, so it cannot be read as contradicting Import; Import instead carries the bridge, stating that copies join the collection automatically when their destination is already a member, which teaches membership-by-folder at the one moment it matters. The empty-search message now carries the action that widens the collection rather than naming a shortcut the user has to go find. Eight strings that nothing displayed are removed. The durable theory is owned by [collections](collections.md). Changes thirteen translatable strings, adds one and removes eight, all translated in the 13 catalogs; the word for "collection" is also normalized in Russian, Ukrainian and Chinese, where Chinese had been using 收藏 and 收藏夹 — this catalog's words for Favorite and favorites — so `Collection folders` read as "Favorites folder".

- **Modal decision dialogs**: every modal that asks the user to decide now states its outcome, keeps the answer it was given, and does its work off the UI thread. Rotate no longer silently does nothing outside a folder — it rewrites files in place, so it is gated on the same eligibility test as the operation itself. Permanent deletion always confirms, even with deletion confirmations turned off, because the recycle bin is what made the unconfirmed case recoverable. Sending diagnostics and writing the desktop-background image both ran their network and encode work on the UI thread with the window frozen and no result; both now run on a worker behind the standard progress dialog and report success or a concrete failure. A failed update check says the check failed instead of reporting that you are on the latest version. Favorite tags gained OK and Cancel, so `Escape` discards the edit instead of committing it. The email options dialog edits a copy and, when the size limit has no positive dimension, reopens with the values intact and the reason shown, rather than committing an unusable setting. Collection options no longer runs Defragment and compact from inside a dialog the user can still cancel; the maintenance run is started after that dialog closes, and its busy window names the operation instead of saying "Processing…". Maintenance's `Clean database and reindex` option now does what it says: only the database work runs behind the busy window, and the collection is then re-read from the files in the background under the normal indexing progress, rather than being restored from the in-memory cache the reset exists to discard. Copy and Move prefill the destination with the most recent folder. Advanced search reports that no criterion was selected instead of closing onto an unchanged view. Busy and cancel windows are anchored where the modal they follow was, so a multi-phase flow no longer hops across the desktop. Playing media is paused by every modal that takes the window, and two dialogs that destroyed their own frame after `show_modal` had already destroyed it no longer do. Adds three translatable strings, translated in all 13 catalogs.

Additional reliability changes:

- A requested `.original` backup must succeed before replacement starts; failure leaves the destination unchanged.
- Copy/move results report paths actually created after Windows collision rename.

- **Related items**: `Related items` answers the question it always claimed to. It previously reported duplicates only — the four other relations it was designed around had never been implemented, and the capture coordinates it collected from the item were passed to the matcher and dropped. It now reports possible copies, the same album, the same series, the closest capture times, and the closest capture places, each as its own group ordered by closeness. An item that qualifies several ways is reported once under its strongest relation, so nothing is listed twice. Closeness bounds the answer instead of a threshold the user has to tune: each relation reports at most the 64 closest items, with an outer window so a sparse collection cannot fill a group with items that are only nearest by default. Capture time means capture time — a collection copied in one pass shares a file time, which would otherwise make every item in it equally and meaninglessly close. Counting and displaying a related search share one bounded path, so a count can never disagree with the set shown. A related search saved as a favorite still rebuilds every field the relations compare from the index, so reopening it answers with the same relations. The command was also labelled with its own tooltip text; it now has a name and a tooltip. The durable behavior is owned by [design](design.md#related-items). Changes two translatable strings and adds six, translated in all 13 catalogs.

- **Same picture, different file**: duplicate detection now recognises a copy that shares no name, size or checksum with its original - a re-encode, a re-save, a resize. Two items that share an exact capture time and agree on nothing else are compared as pictures, using a 64-bit DCT perceptual hash. Decoding never happens on the index walk: it notes a bounded batch of pairs it could not judge, a worker hashes those files at the hash's own extent so a JPEG scales in the DCT domain rather than decoding in full, and the pass runs again, converging over several rounds. Every attempt is recorded, including a refusal, so no file is ever asked for twice. An image with too little detail to identify - a blank frame, a solid colour, a scanned page - is declined rather than matched, which is the usual way perceptual duplicate detection embarrasses itself. A rotation is a different picture and is not claimed as a copy. The result feeds the one duplicate-group computation, so `@duplicates`, presence and `Related items` all report it; none of them can disagree about what a copy is. On the test fixtures the separation is decisive: a resized copy scores 0, a rotation 30, an unrelated photo 32, against a threshold of 6. Adds a `phash` column to the index cache through the existing idempotent upgrade. No new translatable strings.

- **Files that only look like media**: an extension is no longer taken as proof. `.ts` is both an MPEG-2 transport stream and a TypeScript file, so the header decides: a run of packets on the `0x47` sync byte at a 188, 192 or 204 stride, read before the decoder sees the file. A source file is refused outright instead of part-opening as a stream with nothing in it, and the selection panel drops the transport for a file that could not be opened, so a scrubber no longer offers a position in something there is no way to play. Six extensions whose only media claim was an obscure or output-only ffmpeg format are removed — `vb`, `cgi`, `idx`, `chk`, `bit` and `c2` — because each collides with a far more common non-media use, and `.chk` had no demuxer at all, so nothing carrying it was ever openable. `.raw` is deliberately kept: it is a real Panasonic and Leica raw extension, and dropping it would hide photographs. Files with the removed extensions reclassify to `other` on next start with no reindex, because the type is derived from the name rather than stored. The read path is owned by [file I/O](file-io.md). No new translatable strings.

Only a top-level window gets `WM_DPICHANGED`: a modal dialog owns its context and handles it correctly, but a **child control host** — the Import, Sync, Rename, Tags, Locate, Convert and Edit panels, created through `create_dlg(..., false)` — is neither a control nor a frame, so it appeared in neither list the app frame notifies and kept the scale its draw context was created with while the native controls inside it were re-fonted from the shared owner context. A **bubble** shares the app's context and so cannot handle the message at all; its font size was refreshed on every show but its layout metrics were frozen at creation. The parent now tracks its child hosts, with the same expiry pruning `_child_frames` uses, and hands each one the change; the bubble refreshes its metrics where it already refreshes its font size. The metric block, which had been copied into three places, is now `frame_base::update_dpi_metrics`. This also closes the same gap for the large-font toggle, which runs through the same path. [rendering](rendering.md) gains a section owning how a scale change is delivered to every window that draws.

This pass audited [../src/platform_win.cpp](../src/platform_win.cpp) — the shell property and thumbnail readers, the file handle wrapper, drive scanning and eject, the known-folder resolvers, MAPI, the time conversions and the file-name rule — and found six defects. Two are reachable from data the app does not control: `cache_string_var` assigned a `VT_LPWSTR` straight into a `std::wstring` without testing it for null and asserted on an unexpected `VT_UI4`, so a third-party shell property handler could fault the scan worker or `__debugbreak` a Debug session; and the `PKEY_ThumbnailStream` reader treated a short `IStream::Read` as a complete one, decoding bytes the stream never supplied even though its own comment said it must not. `get_shell_thumbnail` built its path with `to_file_system_path`, which prefixes `\\?\` past `MAX_PATH`, but `SHCreateItemFromParsingName` rejects that prefix — so a file on a long path could never get a shell thumbnail, while `get_cached_file_properties` immediately above it already used `to_shell_path`. `file_crc32` looped forever if `ReadFile` succeeded returning zero bytes, which is what a file truncated by another process after its size was taken does, and the default call takes no cancellation token. The `HBITMAP` from `IShellItemImageFactory::GetImage` was released by hand on each return path and is now scope-bound.

  The sixth is the one behaviour change: `platform::is_valid_file_name` accepted the empty string, control characters, a trailing dot or space, and a reserved device name carrying an extension — `CON.txt` is still the console — so the rename preview marked as usable names Windows will reject or silently alter, breaking the preview-before-run promise in [design](design.md). All four are now rejected. The risk that this over-rejects was checked rather than assumed: `format_sequence` builds its result reversed, so the space it pads a `?` placeholder with lands as a *leading* space, which stays legal; only a template that literally ends in a space or dot is newly refused, and `view_rename` already paints an invalid row in `error_text_color`, so the user sees which name is bad instead of meeting a dead Run button. New coverage: `Should reject unusable file names` for the rule and `Should reject unusable rename targets` for the preview outcome, the latter asserting an ordinary name is still accepted so the guard cannot silently tighten. Seven unused shell declarations left from an earlier thumbnail approach were removed. Four findings are recorded and deliberately unchanged, none of them release-blocking: `platform::file::seek` and `pos` report failure as `-1` widened to `uint64_t`, `tick_count` is a 32-bit `GetTickCount` that wraps at 49 days, `onedrive_root_folder` reads only `REG_SZ` and ignores `REG_EXPAND_SZ`, and `path_from_csidl` passes `app_wnd()` as the owner window from worker threads.

## #189 release note

The reporter reproduced the defect on `1.26.4.1215`, built before commit `d2d0a37` on 2026-07-15. The confirmed cause was a glyph cache surviving font-size changes and mixing old-size and new-size glyphs within one string. The first 1.27.0 fix invalidates both D3D11 and software-renderer glyph caches and restores the saved font size at launch.

That fix was incomplete. A user reproduced the same symptom in a popup on 2026-08-06 after changing the size, running for a while, and returning to the original size: invalidation is only as good as the identity it is keyed on, and the glyph rasters carried no size at all, so a single stale text layout drawn once after a size change poisoned those glyphs for the rest of the session. The size is now part of the glyph identity, so no invalidation is required for correctness, and the two paths that could hand a renderer a second size — the bubble measuring before it knew its font size, and the software backend recording a size without discarding its renderers — are closed.

Pre-release validation must cover both renderers; after publication, request a retest specifically on 1.27.0, including a return to the original size after a long session.
