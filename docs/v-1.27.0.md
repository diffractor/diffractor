# Diffractor 1.27.0

Baseline: 1.26.4, released 2026-07-02 as build `1.26.4.1215`.

This document lists what 1.27.0 changed. GitHub issues are authoritative for issue state and discussion; the linked documents own the durable behaviour. Work deferred past this release, issues awaiting reporter confirmation, and validation still to run are recorded in [post-release context](v-next.md).

## Overview

- **Improved UI, Zoom, rebuilt.** Hold to peek at full detail, or press `Ctrl+Space` for a proper zoom mode that stays put while you pan, compare, and move through your photos. Pinch, drag, double-tap, wheel, or use the corner navigator — and the image sharpens as soon as you stop moving.
- **Search by where a photo was taken.** Type a city, a state, a country, or just click the map, and photos with only GPS coordinates now answer too. Diffractor no longer confidently attaches the wrong town name to a photo — if it isn't sure, it says `Near X` with a direction instead.
- **Finds the same photo saved twice.** A resized copy, a re-export, a re-save, or one you rotated is now recognised as a duplicate even though the file name, size, and checksum are all different. Crops stay separate, and burst sequences and scanned pages don't produce false matches.
- **Related items actually finds related items.** It used to show duplicates only. Now it also shows photos from the same album, the same series, taken around the same time, and taken in the same place — each in its own group, closest first.
- **Rename, Import, and Sync are easier to use and safer.** Each one now walks you through it, shows exactly what it is about to do to every file, and lets you decide what happens when a file already exists before anything is written. Copy and Move do this too, instead of quietly making a second copy.
- **Better photo editing.** Fix converging verticals, warm or cool an image, and let Auto color, Auto straighten, and Auto document do the first pass for you. Auto document sets the same crop and straighten sliders you'd use yourself, so you can nudge or undo any part of it — and none of it freezes the window on a big RAW.
- **Faster, safer edits to your files.** Rating a RAW file no longer copies the whole file to record one star. Writes to network drives, OneDrive, and files another program has open now either work or tell you why they didn't, and never leave stray temporary files behind.
- **Now translated into 13 languages.** Czech, German, Spanish, French, Italian, Japanese, Korean, Polish, Portuguese, Russian, Turkish, Ukrainian, and Chinese.
- **Multiple bugs fixed:**
  - #189 — mixed text sizes after changing the font size
  - #232 — a missing Calibri font flooded the log file
  - #103 — OneDrive reverted ratings and tags after syncing
  - #207 — writes to network drives failed and left temporary files
  - #180 — tagging a file another program had open froze Diffractor
  - #78 — videos displayed with the wrong aspect ratio
  - #61 — video locations never appeared on the map
  - #219 — Korean tags failed to display, add, or search
  - #184 — photos sorted by edit date instead of capture date
  - #215 — Explorer opened every folder in Diffractor

## Features

### Zoom

Specified by [zoom](zoom.md).

- Zoom is one model — a scale and a source-space centre — shared by every input and both rendering backends, replacing the previous ad-hoc magnification.
- Two magnified states, and two names for them: **inspect zoom**, the disposable press-and-hold peek, and **zoom mode**, durable until you leave it. Zoom mode has one entry, `Ctrl+Space`, and one exit, `Escape`, which peels a single layer per press and never closes the view while the image is still magnified.
- `Fit` is calculated, not stored, so it recalculates through resize, DPI change and navigation. Adds fit variants and a fixed zoom ladder that steps reversibly through `Fit`.
- Pointer anchoring keeps the point under the cursor still through a scale change, including one that rearranges the layout. The source-space centre is carried from one image to the next.
- Region zoom, nonlinear pan, auto-pan, precision wheel accumulation, and touch pan, pinch and double-tap.
- A corner navigator: a persistent interactive control in zoom mode, information-only during inspect zoom.
- Interactive and settled sampling tiers upgrade image quality when the view stops moving. Decoded-image retention is bounded and adjacent images are prefetched.
- Zoom mode hides the browsing chrome, so it reduces the command vocabulary to operating the zoom, moving through the sequence with the page keys, and grading — rating, colour label, reject and to do. Every other command is an inert, silent no-op. The grading vocabulary is shown, not hidden: a row of inline checkable controls sits bottom-right reporting the current value of everything zoom mode can change, and the same controls appear in the Items and fullscreen panels.
- Comparison panes carry `A` and `B` above their own image with the active pane marked; the marker moves to the top-right corner at title size when a pane is magnified. `Tab` or clicking a marker switches panes, and flipping carries the scale and place. No divider is painted over a magnified image. Comparison zoom can be linked.

### Locations and location search

Specified by [locations](locations.md). Resolves baseline defects 1, 2, 3, 4, 5, 7, 8, 9 and 10.

- Every location term resolves a place instead of matching a stored field, so `place:`, `city:`, `state:`, `country:`, `loc:` and `near:` answer for items that carry only GPS coordinates.
- Places gain qualification levels and a single name composer, so headers, bubbles and search terms all use one identity.
- Attribution is bounded by a population-scaled radius. A confident wrong name becomes `Near X` or `Remote area` plus a bearing.
- Clicking the map emits the same readable radius-and-bearing `loc:` term a user could have typed.
- A no-results location search offers Widen and drop-qualification recovery.
- A places breakdown strip. Each chip is labelled at the smallest name form unique within the strip, so two Londons read `London, United Kingdom` and `London, Canada`, and a chip's count and its click are the same question.
- The shipped gazetteer is regenerated from a current GeoNames snapshot: 262,411 records, 3.0 MB smaller, deduplicated so that records which cannot describe different places are collapsed with every spelling kept as an alternate name.

### Duplicates and related items

- **The same picture in a different file is found.** Duplicate detection now recognises a copy that shares no name, size or checksum with its original — a re-encode, a re-save, a resize, or a quarter turn — using a 64-bit DCT perceptual hash over items that share an exact capture time.
- Rotation is recognised rather than missed: all four orientations are hashed from the pixels and kept together, which covers every relative rotation. A crop remains a different picture and is not claimed.
- Shape narrows the candidates before anything is decoded, and a transposed neighbour still counts because a quarter turn transposes the stored extent.
- Continuous shooting never produces a rotated frame, so only a same-orientation match counts as evidence of a burst; the burst rule is unweakened.
- An image with too little detail to identify — a blank frame, a solid colour, a scanned page — is declined rather than matched.
- Hashing never happens on the index walk. Unjudged pairs are noted in bounded batches, a worker hashes those files at the hash's own extent, and the pass converges over several rounds. Every attempt is recorded, including a refusal, so no file is asked for twice.
- One duplicate-group computation feeds `@duplicates`, presence and `Related items`, so none of them can disagree about what a copy is.
- **`Related items` reports five relations**, not just duplicates: possible copies, the same album, the same series, the closest capture times, and the closest capture places — each its own group, ordered by closeness. An item that qualifies several ways appears once, under its strongest relation.
- Closeness bounds the answer instead of a threshold to tune: at most the 64 closest items per relation, with an outer window so a sparse collection cannot fill a group with items that are only nearest by default.
- Capture time means capture time, so a collection copied in one pass does not make every item equally close.
- A related search saved as a favorite, or typed into the address box as text, rebuilds every compared field from the index and answers with the same relations. A path outside the collection degrades to name and date matching.
- The durable behaviour is owned by [design](design.md#related-items).

### Photo edit

- Perspective correction on both axes, temperature and tint, and three automatic adjustments: Auto color, Auto straighten and Auto document.
- Each automatic adjustment analyses a decoded copy on a worker and applies its result only if the same photo is still displayed, so a large RAW no longer stalls the window. Each states that it found nothing rather than appearing to do nothing.
- Auto document proposes its correction through the straighten, perspective and crop controls you already have rather than baking a rectified page: the image morphs, the crop stays a rectangle bounded to the page, and every chosen value appears in the sliders so it can be tuned or undone one control at a time.
- Preview compares the original against the edited result. `Escape` peels one layer per press rather than discarding the edit, and editing another item from inside the view prompts before losing changes.
- One editable-photo test decides entry, the selector strip and Save+Next/Back, so navigation stays inside the photos the view can actually edit instead of stranding you on a video, folder or unsupported file.
- Saving pixel edits to a format Diffractor cannot write asks for the destination, so an existing sibling JPEG — the usual RAW+JPEG case — is confirmed before it is replaced.
- Save options (keep an original backup, JPEG quality, WEBP quality, WEBP lossless) moved into a section under the colour controls; the `Change save options` command and its dialog are gone. The panel opens with a sentence describing what the view does, matching the other task views.
- Metadata editing was removed from this view; tags, rating and description belong to their own tasks, per [design](design.md).

### Guided file operations

- Rename, Import and Sync follow Scope → Target → Options → Analyze → Review → Run → Results.
- Analysis runs off the UI thread; Run uses the reviewed path plan. Each row is held to the files it named: Run revalidates that row alone immediately before acting, rather than re-deriving the whole plan. Over a network share or a camera card this removes a second full scan of both sides.
- A row that no longer matches what was reviewed writes nothing and is reported as failed with the reason; the rows that still match still run, instead of one changed file discarding the whole run.
- One collision policy applies to a primary file and its sidecars as a logical group. Block Run disables Run, Skip leaves originals, Replace is explicit, and Auto-rename uses one shared suffix.
- Cancellation classifies every unattempted row. Retained Results distinguish success, failure, ignored and canceled rows.
- Import records Move history only for fully successful logical items, does not create destination folders for groups it will skip entirely, separates two sources that resolve to one destination, and states the permanence and the true count before a Replace run — the rows the plan will actually write, not every row whose destination happens to exist.
- Sync's controls state what the operation is: `Local folders` and `Remote folder` rather than a source and destination direction it does not have, the copy and delete options separated from the folder picker, and no item-selection strip for an operation that never reads the selection. The index is refreshed after a run, so copied files appear and deleted files disappear without a restart.
- **Copy and Move state their collisions.** Both went through the shell with auto-rename forced on, so an existing destination silently became a second copy. They now name the files already at the destination and offer Auto-rename or Replace — defaulting to Auto-rename because it destroys nothing — with Cancel as the third answer. The collision test reads the destination once rather than querying per item, so the number of selected files no longer decides how many network round trips happen before the prompt opens.
- A requested `.original` backup must succeed before replacement starts; failure leaves the destination unchanged. Copy and Move results report the paths actually created after a Windows collision rename.

### Selection panel and pin

Specified by [selection controls](selection-controls.md#release-scope).

- Comparison is decided by a file-trait profile rather than by there being two items, so an image/video pair summarizes instead of producing a meaningless comparison table.
- Presence has its own compare/count badge, with detailed status and related items in its bubble rather than in the title.
- Location, Tags and Description close the singular panel and are stated even when empty, each with the affordance that opens its own task.
- The six-tag cap applies in both densities, and comparison rows render from whichever metadata snapshot has arrived.
- The singular panel reads as two groups split by the file: Viewing carries playback options, Slideshow, Pin, orientation, RAW preview, Scale up and Fullscreen; Actions carries reject/label, rating, rotate, Edit, Open and Tools.
- Previous and Next are gone from the Selection summary panel, which has no single item to advance from. Fullscreen keeps camera, dimensions, album and artist.
- **Pin** is now present in both panel forms that can compare — the singular viewing group and the head of each comparison column, alongside Unselect and Delete as the three ways a comparison ends. It previously existed only in the singular non-media table, where comparison is impossible.
- The held item is marked in the items list in both detail and thumbnail presentations, so pin is visually distinct from selection. The command reports and releases the item it holds instead of silently moving the pin to whatever has focus, unselecting one item no longer releases a pin held on another, and a pin is released when its item stops being visibly selected, so a search, filter or inverted selection cannot leave a pin you cannot see.

### Commands, menus and dialogs

- **Each command appears in one place.** The media context menu no longer restates the zoom commands, tools and playback toggles its own submenus hold; zoom commands, including `Flip comparison panes` and the fit variants, are gathered under one `Zoom` submenu with `Navigator` nested beneath it. The items context menu drops the entries duplicated from `Navigate` and `Display options`. There is one definition of a tool and one grouping list, shared by menu and toolbar. The main menu's seven settings entries collapse into a single `Options` submenu. Popup menus now nest more than one level, which the previous Windows menu builder silently flattened.
- **Every command is gated on the surface where its effect is visible**, per [command availability](design.md#command-availability). Sidebar, detail size, thumbnail size and large-item highlighting are offered in Items rather than also in Fullscreen where they change nothing; verbose metadata is offered in Fullscreen, where it does change what is drawn; extend-selection browse commands require items to browse; Close and Items are tested by view alone.
- **A command you cannot run says why.** Grading and edit commands that fail whole-selection eligibility stay visible and dimmed carrying the reason the operation itself would report. Rate or Label is gated on the same test as the ratings and labels inside it, so the menu cannot open onto commands that all fail. The unsupported-type message names the extension it is refusing and states that no sidecar is written for it.
- Batch metadata offers the vocabulary each field accepts: Genre is a picker filtered by the traits of the selection and merged with the genres already in the collection, with an explainer that `;` separates values; Rating is a star and Reject control bound to the pending batch value rather than a number spinner.
- Scale up defaults off, and its help states the off behaviour first.
- **Every modal that asks you to decide states its outcome, keeps the answer it was given, and does its work off the UI thread.** Permanent deletion always confirms, even with deletion confirmations turned off, because the recycle bin is what made the unconfirmed case recoverable. Sending diagnostics and writing the desktop background now run on a worker behind the standard progress dialog and report success or a concrete failure. A failed update check says the check failed rather than reporting you are up to date. Favorite tags gained OK and Cancel, so `Escape` discards. The email options dialog edits a copy and reopens with the reason shown rather than committing an unusable size limit. Collection options starts maintenance after the dialog closes rather than from inside a dialog you can still cancel, and its busy window names the operation. Copy and Move prefill the destination with the most recent folder. Advanced search reports that no criterion was selected. Busy and cancel windows are anchored where the modal they follow was. Playing media is paused by every modal that takes the window.
- `Clean database and reindex` now does what it says: the database work runs behind the busy window and the collection is then re-read from the files under normal indexing progress, rather than being restored from the in-memory cache the reset exists to discard.
- **Eject** locks and dismounts the volume before removing it, so a drive still being written to is reported rather than torn away, and removal falls through to the device node — the only mechanism that removes a USB or external disk. Scanning and ejecting run on a worker. Each drive is listed as `Eject X:\` with its label, capacity, used space and filesystem as translatable parts, omitting whatever the drive does not report; a machine with no removable drive says so; a failure is reported after the dialog closes. The command is available from every view.
- Starting a task from fullscreen — Edit, Tags, Locate, Rename or a metadata batch — leaves fullscreen and keeps the item the task targets, instead of opening the task behind a hidden top bar with its toolbar invisible.
- A running slideshow reports itself on the Slideshow control: checked, a pause icon, and a fill along its base showing how much of the current photo's delay has elapsed. The control is now shown for video and audio too, so a slideshow can be seen and stopped whatever it landed on.

### Files, metadata and formats

Read and write paths are owned by [file I/O](file-io.md); property mapping by [metadata](metadata.md).

- **Rating a RAW file writes only its sidecar.** It previously staged a full copy of the media file and swapped it in — a 60 MB copy to record one star — even though the edit only ever reached `<name>.xmp`.
- In-place metadata writes are now gated on a container allowlist rather than on "an embedded XMP packet exists". The old gate admitted MP3, WAV and AVI, whose handlers relocate the whole payload inside the live file with no temp, so an interrupted rating could destroy the file. ISO base media is admitted without requiring an existing packet, so the first rating on a camera video no longer copies it.
- A write's own re-scan now happens behind the write, while the cache-coherent handle is still valid, so the index, the photo display and the video player all see the bytes that were written instead of reopening the file by name.
- Network and locked-file writes are hardened: extended UNC paths, bounded lease-break retries, durable flushes, a OneDrive-visible modified date, cleanup after a failed update, and a logged reason for every failure instead of a bare code.
- Authoritative XMP tag deletion, MP4/MOV `Xtra` and ASF interoperability with Windows, additional embedded-XMP formats, EXIF DateTimeOriginal precedence for the media-created date, `;`-separated multi-value genres, and binary EXIF comment filtering.
- **An extension is no longer taken as proof.** `.ts` is both an MPEG-2 transport stream and a TypeScript file, so the header decides — a run of packets on the `0x47` sync byte at a 188, 192 or 204 stride, read before the decoder sees the file. A source file is refused outright instead of part-opening as an empty stream, and the selection panel drops the transport for a file that could not be opened, so a scrubber no longer offers a position in something unplayable.
- Six extensions whose only media claim was an obscure or output-only ffmpeg format are removed — `vb`, `cgi`, `idx`, `chk`, `bit` and `c2` — because each collides with a far more common non-media use. `.raw` is deliberately kept: it is a real Panasonic and Leica raw extension. Files with the removed extensions reclassify to `other` on next start, with no reindex.
- `platform::is_valid_file_name` now rejects the empty string, control characters, a trailing dot or space, and a reserved device name carrying an extension (`CON.txt` is still the console), so the rename preview no longer marks as usable a name Windows will reject or silently alter.

### Rendering and text

Owned by [rendering](rendering.md).

- Glyph caches in both backends are keyed by face **and** em size. A glyph index is only meaningful inside its own face, and a face carries no size, so the previous key let one face's glyph be drawn from another face's raster and let an earlier size's raster serve later text — which is what made a font-size change stay wrong for the rest of the session.
- A DPI or large-font change now reaches every window that draws, including child control hosts (Import, Sync, Rename, Tags, Locate, Convert and Edit panels) and bubbles, neither of which receives `WM_DPICHANGED` itself.
- Fonts shared with native controls are tracked and re-fonted as a generation, so a size change can no longer leave a control holding a recycled GDI handle.
- The software backend's shadow now matches the hardware quadrant nine-slice, so the two backends draw the same thing.
- The video hand-off no longer blocks the UI thread for a full second on a held keyed mutex; the wait is bounded and a failed release rebuilds the shared chain.
- Roughly forty further defects in GPU, GDI and COM object lifetime, thread placement and cache keying were found and fixed across both backends, the Win32 UI layer and the shell and platform code. None changes appearance; all were leaks, unchecked failures, or state that could outlive its owner.
- The audio visualizer no longer stays blank for the rest of the session after a device loss.

### Collection comprehension

The durable theory is owned by [collections](collections.md).

- About, Collection options, the indexing message, the in-collection and outside-collection reports and the empty-search message now state one idea in one vocabulary: the collection is the folders you choose including their subfolders, indexing them is what makes search, duplicate detection and totals cover everything at once, and changing that declaration changes only what Diffractor knows.
- The "no files are moved or copied" promise is scoped to defining the collection, so it cannot be read as contradicting Import. Import carries the bridge instead, stating that copies join the collection automatically when their destination is already a member.
- The empty-search message carries the action that widens the collection rather than naming a shortcut you have to go find.
- Eight strings that nothing displayed are removed.

### Installer and shell

- Desktop shortcuts are created only on a fresh install, not on launch or update.
- The folder verb is registered under `Directory\shell` rather than changing the default folder-open command.
- The installer replaces its own data files unconditionally rather than only when newer, so an update cannot keep a stale `location-places.txt` or translation catalog.
- Uninstall removes legacy entries and the Explorer per-extension Open With advertisement it created.

### Languages

- 13 catalogs — Czech, German, Spanish, French, Italian, Japanese, Korean, Polish, Portuguese, Russian, Turkish, Ukrainian and Chinese — each complete, with every source string translated rather than falling back to English.
- Localized place names in search and in the sidebar.
- Korean tag parsing, add and remove, search, NFC/NFD equivalence, metadata round trip and fallback-glyph rendering.
- The word for "collection" is normalized in Russian, Ukrainian and Chinese. Chinese had been using 收藏 and 收藏夹 — that catalog's words for Favorite and favorites — so `Collection folders` read as "Favorites folder".

### Also fixed

- A photo whose background prefetch failed was stranded at thumbnail resolution with no error and no retry, for as long as the texture stayed cached — and the failure is transient by nature, so the file was usually readable by the time you arrived at it.
- A related search that arrived as text — typed into the address box, or restored from a favorite — crashed on the first indexed item compared.
- `Clean database and reindex` regenerated thumbnails only. The in-memory index kept every scan stamp, so no file was ever re-read.
- The Items view kept claiming its working set after switching to another view, re-queuing offline and displayed-item scans every 1.5 s for a grid that was no longer drawn.
- The Items view never released the previously displayed item's media element when selecting an archive or other non-media file, holding its decoded surface and player references through the next selection.
- Independent radio sets in one control host shared a single platform group, so choosing an Import collision policy cleared the source, and choosing a source reset the policy.
- Sync resolved the owning local root with the file name instead of the relative folder, so with the default two-root collection any remote-only file invalidated the whole analysis. Every Sync analysis failure, including an unset remote folder, reported the internal-fault message.
- Import and Sync Results omitted every ignored row, so the list you approved did not match the list the run reported.
- The video player's file handles were released around a write but the display still pointed at the closed session, and a reopen could land after the next teardown and hold the file open across the rename it was for.
- The place breakdown built every chip label at a fabricated qualification level, so three different place, region and country keys all rendered as `Singapore`.
- Rotate silently did nothing outside a folder; it rewrites files in place, so it is gated on the same eligibility test as the operation itself.
- The tile cache derived its retention cutoff from the local clock, so on a share that stamps files ahead of that clock nothing was ever trimmed.
- The Eject dialog reported a failure by re-entering the modal loop from inside the running button, destroying the controls — and the function — it was executing on.
- A shell property handler returning an unexpected type could fault the scan worker; a short thumbnail-stream read was treated as complete; and a file on a long path could never get a shell thumbnail.
- `Related items` was labelled with its own tooltip text; it now has a name and a tooltip.
